I like many engineers have had my qualms with how AI has intruded on workflows. Nevertheless, working a job today means playing with it, trying to figure out how to work faster without losing quality. While I was resistant to this change when I was first asked to make it, I must admit something it has forced me to learn is planning. I now have a much more formalized workflow from conception to implementation. Before it was very much I had an idea and just plunged myself into code. If it was complex or was a bug that had a long data flow involved I may whiteboard it, but largely this whiteboarding only went so far as it took for me to mentally map the flow. 

When I was tasked with utilizing Agents in my workflow, I typically felt a need to understand everything of how the eventual code would work. Creating things like acceptance criteria and having a set of files that the data should route through before I even wrote a single line of code or had the AI start working. This helped the code come out properly almost every time, but now that I no longer have access to premium models, I have found that this development was one that, despite avoiding the effort in the past, is incredibly beneficial to ensuring things stay clean. 

That probably sounds obvious to more senior engineers, and to an extent it was obvious to me as well, but obvious improvement that requires large changes to your workflow can go undone for some time, and this stayed on the backlog longer than it should have. 

As insinuated in the title, I'm trying out game development, and this planning has benefitted me immensely, as when I was learning how some of it worked I created messy code, but now that I understand the flows I have almost all of the app mapped out in canvases, so implementation will be an absolute breeze. Before this addition to my workflow, I probably would have found this work to be slough, taking up so much memory in my mind, but now it is just tracing lines so to speak.
